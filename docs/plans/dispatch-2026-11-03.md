Title: Input slice 2: gamepad device on the action layer, hot-plug prompts, beat haptics (#2027 slice 2)

## Context / motivation
#2061 landed #2027 slice 1: `src/core/input/actions/` (action-layer.ts, bindings.ts, frame.ts, keyboard-mouse.ts, settings-store.ts, types.ts) with a context stack (gameplay / build / gizmo / photo / menu), rebinding persisted through settings-store.ts, `input.get(action)` / `input.onPress(...)`, `input.lastDevice()`, and `docs/INPUT.md`. The `Device` union in types.ts already includes 'gamepad' and `lookSensitivity` is already `Record<Device, number>`, but there is no gamepad device: `navigator.getGamepads` has zero callers in `src/`. The epic's slice list is (1) action layer + kbm, (2) gamepad + haptics, (3) touch, (4) XR spike, (5) XR locomotion. This is slice 2. Active focus areas it serves: music reactivity (haptics on kick-drum beats) and the player-controls foundation that build mode on any device (#1974) and phone joins to shared worlds (#1975) need.

## Proposed approach (first pass)
1. `src/core/input/actions/gamepad.ts`: a device that polls `navigator.getGamepads()` once per frame from the same place keyboard-mouse.ts is sampled (the INPUT phase via frame.ts / `updateInputActions`), using the Standard Gamepad mapping. Radial deadzone on both sticks, a response curve on `look`, triggers as analog `value`. It writes raw sources into the action layer exactly as keyboard-mouse.ts does; game code is untouched.
2. Default bindings in bindings.ts for every ActionId that has a keyboard default: move (left stick), look (right stick), jump (A/cross), dash (B/circle or left trigger), interact (X/square), fire (right trigger), ability slots (d-pad), build.toggle (Y/triangle), build.place / build.remove (triggers inside the build context), build.rotate / build.scale (bumpers + stick), undo/redo (back + bumpers), photo.toggle, menu (start). Rebinding rows for gamepad sources in the accessibility menu, reusing `isRebindableSource` / `bindingLabel` / `formatSource`.
3. Hot-plug: `gamepadconnected` / `gamepaddisconnected` set `lastDevice()`; any HUD prompt that reads `lastDevice()` switches glyphs. Announce connect/disconnect through systems/accessibility.ts.
4. Beat haptics: subscribe to the existing `BeatSync` callback (`src/audio/beat-sync.ts`, `BeatCallback`) and call `gamepad.vibrationActuator.playEffect('dual-rumble', ...)` lightly on kick beats and more strongly on the chord-strike / geyser-launch events music reactivity already raises. Off by default; a toggle in the accessibility menu persisted in settings-store.ts. Feature-detect `vibrationActuator`; never throw on pads without it.
5. `docs/INPUT.md`: a Gamepad section (mapping table, deadzone/curve settings, haptics toggle, how to add a gamepad binding).

## Acceptance criteria (rough)
- With an Xbox or PlayStation pad in Chrome: walk, look, jump, dash, every ability, build mode (place, remove, rotate, undo) and photo mode work with no keyboard. Unplugging mid-session falls back to kbm without a stuck axis.
- `tests/input-gamepad.test.ts` (tsx, same harness as tests/input-actions.test.ts, a fake `getGamepads`): deadzone and curve math, Standard-mapping button → action resolution in each context (in `build`, `fire` does nothing; in `menu`, no gameplay action fires), hot-plug flips `lastDevice()`, rebinding a gamepad source persists through settings-store.ts. Wired into `test:fast` (appended at the end).
- Haptics: off by default, toggle persists, no call when `vibrationActuator` is absent, no effect queued more than once per beat.
- `npm run typecheck` 0, `npm run lint` at or below baseline, `budget:check` green with the `app` chunk unchanged (the device is small; if it is not, lazy-load it on first `gamepadconnected`).
- No file outside `src/core/input/**`, `src/ui/accessibility-menu*.ts`, `tests/input-gamepad.test.ts`, `package.json`, `docs/INPUT.md` changes.

## Open questions for Noah
- Does the raw-key ESLint rule from slice 1 (currently `warn`, 21 files outside core/input still attach key listeners) get ratcheted here, or stay a separate ticket?
- Haptics source of truth: the `BeatSync` callback, or the kick-drum channel event in music reactivity? Which one is already filtered per track?
- Build-mode radial palette on a shoulder button: in this slice, or wait for slice 3 (touch) so the same palette serves both?
