# Swarm state — #1448 WebGPU single-device unification

**Task:** One owned WebGPU device (renderer-owned), shared with compute + particles, with
device-lost recovery, explicit renderer context options, and a boot-time context log.
**Branch:** `claude/webgpu-single-device-odv4mq`
**Issue:** #1448

## Ground truth (verified 2026-07-28)

`grep -rn "requestDevice\|requestAdapter" src` →

| File | What it does today |
|---|---|
| `src/compute/gpu-compute-library.ts:93,102` | own `requestAdapter` + `requestDevice` (128 MB storage, wgSizeX 256) |
| `src/particles/compute-particles.ts:468,478` | own `requestAdapter` + `requestDevice` (same limits), once per particle system |
| `src/utils/startup-profiler.ts:195-247` | monkey-patches `navigator.gpu.requestAdapter` for buffer/shader telemetry — does NOT create devices |
| `src/systems/performance-budget/performance-budget-core.ts:208` | opportunistic `requestAdapter` (adapter-info only, no device) — **OUT OF SCOPE** (`src/systems` owned by another agent) |
| `src/core/init.ts:144` | `new WebGPURenderer({ canvas, antialias: true })` — Three requests adapter+device internally |

So the happy WebGPU boot currently performs **3+ `requestDevice` calls** (Three + compute lib +
one per compute particle system).

three@0.171.0 facts confirmed from `node_modules`:
- `WebGPUBackend.init()` reads `parameters.powerPreference`, `parameters.requiredLimits`,
  `parameters.alpha` (default `true` → `alphaMode: 'premultiplied'`), and stores `this.device`.
  It does **not** retain the adapter.
- `Renderer.init()` **throws** if called twice after completion → must guard with
  `hasInitialized()`. Concurrent callers share `_initPromise`.
- `Renderer.onDeviceLost` is an overridable hook, defaulting to a `console.error`.

## Plan

1. `src/rendering/gpu-context.ts` (NEW) — single owner. Captures the adapter Three requests
   (one-shot `requestAdapter` wrapper, **no extra request**), awaits `renderer.init()`, adopts
   `renderer.backend.device`, registers `device.lost` + `renderer.onDeviceLost`, publishes
   `window.__gpuContext`, and exposes `getGpuContext()` / `awaitGpuDevice()`.
2. `src/rendering/webgpu-limits.ts` — adopt limits from the shared context; expose the
   storage-buffer/workgroup ceilings so compute stops hardcoding them.
3. `src/core/init.ts` — renderer construction only: explicit `powerPreference`, `antialias`,
   `alpha`, `requiredLimits`; arm the GPU context; WebGL path gets matching `powerPreference`.
4. `src/compute/gpu-compute-library.ts` + `src/particles/compute-particles.ts` — consume the
   shared device, fail closed to CPU/WASM.
5. `src/utils/startup-profiler.ts` — keep telemetry hooks, no device ownership; read adapter
   info from the shared context.
6. `docs/WEBGPU_CONTEXT.md` — owner, limits matrix, device-lost policy.

- Design notes:
